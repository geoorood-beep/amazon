# V2.0 广告报表聚合工具实施记录（2026-08-03）

> 本文件是实施和验收记录。当前工具入口见 `tools/ad_report_aggregator/README.md`；字段合同见 `contracts/ad-report-aggregation.md`。

## 本次纳入 V2.0

- 第 05 层新增 `ACTIVE_LOCAL_TOOL` 六表聚合程序；
- Python 负责文件识别、字段标准化、父级链、窗口聚合、对账和 Data Quality；
- 工作簿由确定性表格运行时生成，输出十个可筛选、可追溯 Sheet；
- 智能体优先读取紧凑的 `ad_decision_packet.json`，减少重复读取六张原始表的上下文消耗；
- 原始报表不修改，全部通过文件 SHA-256、Sheet、周期和有效行数追溯；
- 工具只接收本地文件，不改变 MCP/API/外部服务器 `PLACEHOLDER_NOT_ACTIVE` 状态；
- Amazon 后台自动执行继续关闭。
- 新增 7/14/30 天重叠报表名称键分析入口；30 天每日明细为唯一历史事实源，其他重叠窗口只校验。
- 支持恢复读取错误声明 `A1` 或整表维度的 Amazon/WPS XLSX；店铺口径独立于广告归因口径。

## 真实数据边界

标准六表模式继续使用合成数据做完整不可变 ID 和父级链验收。名称键模式已用 27 份真实来源文件验收 7/14/30 重叠去重、异常 XLSX 维度、老品短周期、店铺口径分离和证据索引，但这些源文件缺 Campaign / Ad Group / Target 不可变 ID，因此只允许分析，执行状态固定为 `BLOCKED_MISSING_IMMUTABLE_IDS`。这不代表所有 Amazon 语言/地区/导出模板均已验收。

第一次使用真实六表时必须：

1. 人工核对六个文件映射；
2. 核对表头别名和归因窗口；
3. 核对 `02_RECONCILIATION` 全部为 PASS；
4. 核对 Campaign → Ad Group → Target → 搜索词父级链；
5. 只有 `DQ_PASS` 才交给老品广告分析。

重叠报表模式还必须核对：主 ASIN、30 天事实源结束日、老品工作簿周期、两个周期空档、所有窗口差异和 `13_ISSUES`。名称哈希 `LOCAL-*` 仅用于分析定位，不能用于 Amazon 后台动作。
