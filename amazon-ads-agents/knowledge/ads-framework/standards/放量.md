# 标准：放量

### R-SCALE-01 投放词放量和搜索词放量分开　【标准】
- 动作：投放词放量看投放结构；搜索词放量必须有当前链接的历史搜索词。新品没有足够历史搜索词时，不套用搜索词放量。
- 出处：总纲 §8、§11
- 落地：引擎加词只用当前链接搜索词报表；成熟度 L3 才解锁

### R-SCALE-02 投放词放量的六种方式（按需选，不是六步都做）　【标准】
| 代号 | 方式 | 做什么 |
|---|---|---|
| S1 | 同级 | 有效的一级或同级词，横向扩结构或意图相近的词（识别规则见 `pending.md` P-09） |
| S2 | 长尾 | 往更具体的下级词扩，保留有效词根和购买意图 |
| S3 | 精准 | 已验证的词改为精准，提价、加预算，必要时独立成组 |
| S4 | 拆组 | 把组里突出的词拆出去单独控预算、竞价、匹配、广告位 |
| S5 | 短尾 | 稳定长尾反测更短、流量更大的词，预算和竞价更严 |
| S6 | 瀑布流 | 在已验证的高层之下加范围更宽或竞价更低的承接层 |
- 出处：总纲 §8.0
- 落地：引擎加词标注 S2 / S3；其余由分析方在方案里标注

### R-SCALE-03 放量顺序　【标准】
- 动作：自动或一级广泛探索 → 表现好的一级词做同级扩展并预判二级词 → 二级广泛 / 词组拿长尾 → 有历史表现的完整搜索词进精准候选 → 精准承接 → 需要时把二、三级、词组或精准拆成独立活动。
- 出处：总纲 §13.8
- 落地：方案报告检查项

### R-SCALE-04 搜索词分层管理　【标准】
| 层 | 进入条件 | 动作 | 退出 / 降级 |
|---|---|---|---|
| 观察 | 有曝光点击，数据不足 | 留在原触发路径 | 明显错词直接否定 |
| 候选 | 相关且出现订单或正向指标 | 标为精准候选 | CVR / CPA 不达标继续观察 |
| 精准 | 历史表现通过 | 单独精准投放，必要时拆活动 | 与原范围层严重互抢时调否定 |
| 高竞价放量 | 精准词能持续花费且达标 | 小步提价、加预算或目标位置溢价 | CPA / ACOS 恶化或自然位无效干预 |
| 低价瀑布 | 高层稳定且仍有增量 | 增加更低竞价承接层 | 数据拆散、内部抬价、无增量 |
| 缩量 / 否定 | 持续低效、错词、无承接价值 | 降价、降预算、关闭或否定 | 有新证据才恢复 |
- 出处：总纲 §11.2
- 落地：候选 → 精准由引擎加词实现（门槛见 `suggestions.md` S-05）；其余为方案检查项

### R-SCALE-05 拆组是为了释放被压住的曝光　【标准】
- 动作：多词组里只有少数词拿到主要曝光时，稳定词留原组；其余有放量资格的词拆到少词组，每组单一词根、单一匹配方式、单一目的；拆后对比实际搜索词，确认新增流量来自目标词；一次只改拆组或竞价中的一个。
- 出处：总纲 §13.7
- 落地：方案报告检查项（拆组起始竞价见 `suggestions.md` S-07）

### R-SCALE-06 太挤就拆，太散就合　【标准】
- 动作：少数词抢走预算和曝光 → 拆；活动太多、每个预算都不够、数据积累不起来 → 合并相同目的、词根、层级的活动；层级合理 → 只调表现异常的层。
- 出处：总纲 §13.7
- 落地：方案报告检查项

### R-SCALE-07 瀑布流向下迁移的顺序　【标准】
- 动作：① 选已验证的下级或精准搜索词 → ② 建更精准或范围更小的承接层（验证前不关上级）→ ③ 下级稳定后再小步降低自动或上级竞价 → ④ 比较调整前后总流量、订单、成本，确认不是活动间搬家 → ⑤ 上一层仍能花费且达标时才加更低竞价层，不一次复制完整矩阵。默认是"范围瀑布流"（精准最高、然后词组、广泛、自动），同词同匹配多竞价不是默认结构。
- 出处：总纲 §8.6、§13.9
- 落地：人工复核（层数、竞价差、预算见 `pending.md` P-11、P-12）

### R-SCALE-08 放量前过放量关口　【标准】
- 动作：同时满足才放量——流量可控、数据足够、属于正向干预、自然位未到瓶颈。任一不满足只做小量测试或继续观察。
- 出处：总纲 §1.4、§6.5
- 落地：引擎用成熟度 L3 + 近 3 天未转差 + 品类优质线近似；自然位瓶颈由分析方复核
