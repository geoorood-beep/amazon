# AGENT: 老品推广优化主流程

> 项目作用域：本文件在“陆遥广告智能体”中只处理 Rug / 地毯。完整老品动作必须使用当前 Rug 链接真实报表，不得调用其他类目的历史词、阈值或对象映射。

本 AGENT 是老品推广上层入口。搜索词再投放只是其中 `5.2.5 搜索词与词根诊断` 子模块。

老品推广方案的数据源必须来自当前链接 / 当前 Campaign / 当前广告组的真实报表。`reference/category-history/` 下的类目历史出单词数据只能作为新增选词或新广告候选词参考，不能作为老品诊断、预算、Bid、广告位、趋势、否词、暂停或放量的数据源。

本文中的“历史搜索词”必须先分两类：

- `当前链接历史搜索词`:来自同一链接的搜索词汇总或每日明细，能追溯观察周期和搜索词实际表现。即使仅有这类报表，也可以启用“有限数据老广告优化模式”。
- `类目 / 同类历史搜索词`:来自其他 ASIN、其他产品或 `reference/category-history/`。它们仍然只能做候选词参考，不能启用当前链接的老广告优化判断。

## 老品输入报表命名标准

以后向用户说明老品推广需要导入哪些表格时，必须使用以下固定报表名称。不要用 `Search Term Report`、`Placement Report`、`Targeting Report` 这类泛化英文名替代，除非同时标注对应的标准中文名称。

### 必须导入

| 优先级 | 报表名称 | 主要用途 | 缺失影响 |
|---|---|---|---|
| 必须 | `SP搜索词-按词-每日明细` | 计算近 3 天 CVR、识别出单搜索词、未出单浪费词、词根聚合、放大判断、精准否定 | 缺失后无法判断近 3 天趋势和是否可放大 |
| 必须 | `SP搜索词-按词-汇总` | 查看完整周期累计表现，与每日明细互相校验 | 可用每日明细汇总代替，但稳定性下降 |
| 必须 | `SP投放对象 / 关键词 / 商品投放报告` | 判断投放词、投放 ASIN、匹配方式、Bid、花费、订单、销售额；决定保留、降 Bid、提 Bid、迁移、暂停 | 无法给出投放对象级别的后台动作 |
| 必须 | `SP广告位报告` | 分析 TOS / ROS / PP 的花费、订单、ACOS、CVR；判断广告位溢价加、降、取消 | 无法判断广告位溢价是否合理 |
| 必须 | `SP广告商品报告` | 按 ASIN / SKU / 变体判断哪个子体吃预算、哪个子体转化差；决定拆分、合并、暂停、防守 | 无法判断变体和广告商品层面的优化动作 |
| 必须 | `Campaign / Ad Group 设置表` | 提供 Campaign_ID、Ad_Group_ID、预算、状态、竞价策略、默认 Bid、TOS/ROS/PP 溢价、Campaign 名、Ad Group 名；完整执行模式要求一个 Campaign 恰好对应一个 Ad Group | 只能判断方向，不能输出后台可执行动作 |

### 建议导入

| 优先级 | 报表名称 | 主要用途 | 缺失影响 |
|---|---|---|---|
| 建议 | `SP广告位-每日明细` | 看最近 1 / 3 / 7 / 14 / 30 天广告位趋势，判断短期恶化或恢复 | 只能看汇总，无法判断广告位短期趋势 |
| 建议 | `SP关键词-每日明细` | 判断老投放词本身的趋势，不只看搜索词 | 难以判断投放词是否该保留、调 Bid 或迁移 |
| 建议 | `小时预算 / 小时花费报告` | 判断预算是否过快烧完、是否需要加预算、是否存在时段浪费 | 无法判断预算消耗速度和分时问题 |
| 建议 | `商品业务数据 / 订单目标 / 利润信息` | 至少包含当前订单目标、目标 ACOS 或目标 CPA、售价、毛利、库存、Coupon、Review 星级和数量 | 只能做广告内部优化，无法判断是否值得放量 |
| 建议 | `SPV / SB / SBV 素材与账户条件表` | 判断优质出单词是否能跨广告产品拓量，包含视频素材、品牌资质、Store / 落地页、可投广告产品 | 缺失后只能判断 SP 内部再投放，不能生成 SPV / SB / SBV 可执行新增动作 |

如果用户提供的报表名称不同，先映射到上表标准名称，再继续判断。若无法映射，标记“报表名称不标准 / 需人工确认”，不要自行假设。

## 有限数据老广告优化模式（仅当前链接历史搜索词）

当只导入 `SP搜索词-按词-汇总`，或导入汇总 + `SP搜索词-按词-每日明细`，且词表确认来自当前链接时，不返回“只能报缺失”。应输出词根层的老广告优化方案，但这是“有限数据方案”，不是完整后台执行单。

### 最低输入与数据充分度

| 输入状态 | 允许判断 | 必须写明的不足 |
|---|---|---|
| 搜索词汇总，含观察周期、点击、花费、广告订单、广告销售额 | 词根历史订单、CVR、ACOS、CPA、历史词根优化分、保留 / 复投 / 观察 / 风险候选 | 无法判断近3天趋势、当前广告组、Bid、广告位、广告商品、预算或结构 |
| 搜索词汇总 + 每日明细 | 上述判断 + 近3天 CVR / 近期趋势的有限复核 | 仍无法判断当前投放对象、具体 Bid、广告位溢价、产品变体、预算或 Campaign 状态 |
| 没有观察周期，或缺点击 / 花费 / 订单 / 销售额中任一核心字段 | 只能保留原始词及原始指标对账 | `【缺失数据】不足以生成词根优化分或老广告建议` |

### 允许输出的动作

- 对每个主体相关词根按 `历史词根优化分`、订单、CVR、ACOS和点击样本输出：`保留观察`、`Phrase复投候选`、`Exact候选`、`Broad低预算候选`、`限流 / 否词候选`。
- 词根达标只能写成“待投放对象映射的老广告优化候选”；不得写成已知道哪个 Campaign 或广告组应调整。
- 近期无单、高点击无单或高花费无单词根可以输出“限流 / Negative Exact 候选”，但必须写 `待投放对象映射`，不得直接输出后台否词、暂停或 Bid 改动。

### 禁止伪造的结论

缺少以下报表时，必须在对应模块写 `【缺失数据】数据不足，无法准确判断`：

- 缺 `SP投放对象 / 关键词 / 商品投放报告`:不判断实际匹配类型、具体 Bid、否词执行、投放对象替换或广告组归属。
- 缺 `SP广告位报告`:不判断 TOS / ROS / PP 溢价。
- 缺 `SP广告商品报告`:不判断 ASIN / SKU / 变体的暂停、拆分、合并或防守。
- 缺 `Campaign / Ad Group 设置表`:不判断预算、竞价策略、状态或实施对象。
- 缺每日明细:不判断近3/7/14/30 天趋势，不把累计数据写成最近表现。

## 目标

先沿固定诊断路径判断现有广告为什么好或不好，再通过多层数据聚合确定目标，同时给出老广告优化方案和新广告架构。禁止只看 ACOS 直接调预算或 Bid。

## 阈值调用

CPA、CVR、ACOS 的具体标准不在本文件内硬编码。判断整体效果、广告位效果、广告商品效果和趋势状态时，必须先确认产品类目 / 型号 / 尺寸，再调用：

`agents/category data thresholds.md`

Rug / 地毯必须先按该文件的 `Rug 尺寸类型自动识别与分析阈值路由` 处理：用当前 ASIN / SKU 的尺寸自动识别 `长条 / 门垫 / 区域 / 圆形`，再调用对应类型的 CPA / CVR / ACOS 阈值。`2x4`、`3x6`、`3x7`、`4x10`、`4x12` 和所有短边为 `2.5` 的矩形统一归长条。父体多尺寸或广告组投放多个尺寸时必须逐 ASIN / SKU 分析；无法把广告数据对应到尺寸时，不得套用任一地毯阈值。

如果对应品类阈值缺失，不能自行编造标准，只能输出“品类阈值缺失，无法强判断”。

老品新增广告组或重建广告组必须调用 `agents/promo-output-templates.md` 的统一广告组命名规则，标准最低日预算同样按对应类目 / 型号 / 尺寸的 CPA 正常线上限设置。若当前链接已有稳定目标 CPA 且用户明确要求按目标 CPA 控制预算，可在判断依据中同时展示“用户目标 CPA”和“品类 CPA 正常线上限”，但不能低于用户确认的最低测试预算。

## V1.4 数据质量与执行权限

老品诊断先做数据质量判断，再做效果判断。每次只能输出一个数据质量状态：

| 状态 | 判定 | 权限 |
|---|---|---|
| `DQ_PASS` | 报表类型齐全；日期、时区、币种、归因口径一致；跨报表金额和对象映射通过；不可变 ID 唯一 | 可以生成候选动作，仍需通过独立 Validator |
| `DQ_WARNING` | 存在非阻断缺失、可解释差异或待人工确认映射 | 只允许观察或 `APPROVAL_REQUIRED` 候选 |
| `DQ_BLOCKED` | 关键报表缺失、对象无法唯一定位、跨报表对账失败、日期/币种/归因冲突、阈值空档或多重命中 | 整体状态固定为 `DATA_BLOCKED`，不得生成执行动作 |

完整模式必须使用 `Campaign_ID`、`Ad_Group_ID`、`Target_ID / Keyword_ID` 定位对象。一个 Campaign 在本次输入快照中不是恰好对应一个 Ad Group，或只凭名称无法映射到唯一对象时，必须 `DQ_BLOCKED`。有限数据模式不得因为能识别搜索词就升级为完整执行模式。

V1.4 不修改 `agents/category data thresholds.md` 的数值。当前阈值出现空档、重叠、单位不明或 Rug 圆形未配置时，不得静默选择档位；所有依赖该阈值的强动作必须 `BLOCKED`，等待人工补充或确认。

## 诊断路径

按顺序检查：

1. 数据质量：日期、时区、归因、币种、报表齐全度、跨报表对账、样本量、不可变 ID 和对象映射。输出 `DQ_PASS / DQ_WARNING / DQ_BLOCKED`。
2. 整体效果：按“唯一整体状态”优先级，只输出一个状态。
3. 花费时段：预算消耗率、耗尽时间、小时花费/订单。预算压力可独立只读展示；只有整体状态允许进入局部诊断时，才形成小时节奏候选动作。
4. Bid 与策略：曝光、点击、CPC、转化、实际竞价。判断“Bid偏高 / 合理 / 偏低”。
5. 广告位：按整体状态路由决定是否进入 TOS / ROS / PP 诊断，不再使用模糊的“好 / 不好”入口。
6. 广告商品：ASIN/SKU、父子体、尺寸、花费、订单、ACOS、CVR、CPA、CTR、变体表现。判断“暂停 / 换品 / 拆分 / 合并 / 防守 / 观察”。
7. 搜索词：单词与词根聚合、迁移、否定、相关性。调用 `search-term-reinvestment.md`。
8. 趋势：动作判断使用不重叠的 `D0-3 / D4-7 / D8-14 / D15-30`；滚动 3/7/14/30 天只描述当前水平。主指标与至少一个辅助指标同向才可形成动作。
9. 结构：重复词、预算分散、类型混装、内部竞争。判断“保持 / 合并 / 拆分 / 重建”。
10. 跨广告产品拓量：对达到优质线且稳定的出单词，判断是否从 SP 复制验证到 SPV / SB / SBV；素材或品牌资质缺失时只输出待补，不生成执行动作。
11. 动作仲裁与 Validator：同一对象只保留一个主动作；相反动作冲突必须阻断；候选动作通过独立 Validator 后才进入人工执行表。

## 唯一整体状态

先确定用户的主经营目标，再按以下优先级从上到下命中第一个状态。不得并列输出多个整体状态：

| 优先级 | 状态 | 含义与权限 |
|---:|---|---|
| 1 | `DATA_BLOCKED` | 数据质量为 `DQ_BLOCKED`；不生成动作 |
| 2 | `DATA_INSUFFICIENT` | 样本不足，尤其 `O<2`；默认只观察 |
| 3 | `TARGET_CATEGORY_RISK_CONFLICT` | 用户目标宽于品类风险护栏且实际值处于冲突区；只做高影响审批 |
| 4 | `HIGH_RISK_WITH_VOLUME` | 已达订单目标但命中品类高风险；进入风险诊断，不得称为低效无量 |
| 5 | `HIGH_RISK_WITHOUT_VOLUME` | 未达订单目标且命中品类高风险；进入风险诊断 |
| 6 | `EFFICIENT_AT_TARGET` | 主目标达成、订单达成、优质出单词花费占比达标；保持 |
| 7 | `EFFICIENT_STRUCTURE_RISK` | 主目标和订单达成，但优质出单词花费占比未达标；保持主结构并复核结构风险 |
| 8 | `EFFICIENT_UNDERSCALE` | 主目标达成但订单未达标；检查预算、流量和承接 |
| 9 | `VOLUME_ACHIEVED_COST_ABOVE_TARGET` | 订单达标但成本目标未达成；进入成本优化 |
| 10 | `COST_ABOVE_TARGET_UNDERSCALE` | 成本目标和订单目标均未达成；进入成本与流量联合诊断 |
| 11 | `INCONCLUSIVE` | 输入组合无法形成可靠结论；观察并补数据 |

主目标必须来自用户输入的 ACOS、CPA、订单、利润或结构目标。用户未提供目标时，不得自行假设目标线；只能调用品类阈值描述风险等级，并将目标达成相关状态降级为 `INCONCLUSIVE`。

订单 `O<2` 默认进入 `DATA_INSUFFICIENT`。唯一例外为 `O=0`、归因窗口成熟、达到当前品类停止线、Target 已唯一映射且 `DQ_PASS`；全部满足时只能生成 `APPROVAL_REQUIRED` 的强收缩候选。`O=1` 不适用例外。

## 花费时段诊断

小时花费质量动作按整体状态路由；预算压力可独立只读展示。

### 是否进入小时花费分析

1. 若整体状态为 `EFFICIENT_AT_TARGET` 或 `EFFICIENT_STRUCTURE_RISK`：
   - 不以小时花费快慢评价流量质量，也不据此调整预算、Bid 或广告位。
   - 可以单独展示“预算提前耗尽 / 未耗尽”的 `READ_ONLY` 标志，供人工查看。
   - 动作：保持。

2. 若整体状态允许局部诊断：
   - 开始分析小时数据。
   - 判断预算是否过快、正常或过慢。
   - 必须与订单、主指标和至少一个辅助指标一起决定候选动作。

### 理想累计花费曲线

最佳出单集中在 `06:00-18:00`，使用以下理想累计花费比例作为自动监控基准：

| 时间 | 理想累计花费 |
|---|---:|
| 06:00 | 10% |
| 08:00 | 20% |
| 10:00 | 35% |
| 12:00 | 50% |
| 14:00 | 65% |
| 16:00 | 80% |
| 18:00 | 95% |
| 24:00 | 100% |

计算：

```text
实际累计花费率 = 当前已花费 / 日预算
偏差 = 实际累计花费率 - 当前时间对应的理想累计花费率
```

判断：

| 判断 | 条件 |
|---|---|
| 过快 | 实际累计花费率 > 理想值 + 15% |
| 过慢 | 实际累计花费率 < 理想值 - 15% |
| 正常 | 其他情况 |

### 小时节奏动作

| 花费节奏 | 订单表现 | 判断 | 动作 |
|---|---|---|---|
| 过快 | 达标 | 有效流量但预算提前消耗 | 仅在整体状态为 `EFFICIENT_UNDERSCALE`、趋势同向且预算上限允许时生成加预算候选；否则保持 |
| 过快 | 不达标 | 高价低效流量提前消耗预算 | 不加预算；查搜索词、Bid、广告位；优先降低效位置和高花费无单词 |
| 正常 | 达标 | 投放健康 | 保持 |
| 正常 | 不达标 | 节奏不是主因，可能是转化或流量质量问题 | 查搜索词、Listing、广告位和商品承接 |
| 过慢 | 达标 | 小流量高效率 | 仅在整体状态允许、趋势同向且对象映射完整时生成提高 Bid 或广告位候选 |
| 过慢 | 不达标 | 需求、竞价或相关性不足 | 查曝光、点击率、入口规模和关键词相关性 |

## Bid 与策略诊断

| 数据表现 | 判断 | 动作 |
|---|---|---|
| 曝光少，历史转化好 | 竞价不足 | 提高 Bid，受单次调整上限约束 |
| 曝光多，点击少 | 相关性或 Listing 吸引力不足 | 不盲目提高 Bid |
| 点击达到门槛，无订单 | 风险信号 | 必须继续检查 `O=0`、归因成熟、品类停止线、唯一 Target 映射和 `DQ_PASS`；全部满足也只生成待审批候选 |
| 订单稳定，CPA 达标 | Bid 合理 | 保持或小幅拓量 |
| 订单稳定，CPA 超标 | 成本偏高 | 小幅降低 Bid |
| 花费过快且订单不足 | 抢量过度 | 降 Bid 或改为动态仅降低 |
| 花费过慢且效果良好 | 流量获取不足 | 提高 Bid 或优质广告位溢价 |

## 广告位诊断规则

广告位诊断不是每次都执行。必须先取得唯一整体状态，并确认广告位报表与整体报表日期、币种和归因口径一致。

### 是否进入广告位诊断

| 整体状态 | 是否进入广告位优劣诊断 | 处理 |
|---|---|---|
| `DATA_BLOCKED`、`DATA_INSUFFICIENT`、`TARGET_CATEGORY_RISK_CONFLICT`、`INCONCLUSIVE` | 否 | 补数据、观察或人工审批 |
| `EFFICIENT_AT_TARGET`、`EFFICIENT_STRUCTURE_RISK` | 否 | 保持当前广告位结构，不因局部短期波动调溢价 |
| `EFFICIENT_UNDERSCALE` | 是 | 查优质广告位是否拿量不足 |
| `VOLUME_ACHIEVED_COST_ABOVE_TARGET`、`COST_ABOVE_TARGET_UNDERSCALE` | 是 | 减少低效位置花费，保留高效位置 |
| `HIGH_RISK_WITH_VOLUME`、`HIGH_RISK_WITHOUT_VOLUME` | 是 | 优先识别高花费低效位置，候选动作需审批 |

预算是否提前耗尽独立标记为 `READ_ONLY`，不改变上表路由，也不能单独触发广告位动作。

### 广告位好坏判断

每个广告位分别看：

- 花费占比
- 订单
- ACOS
- CPA
- CVR
- 点击样本
- 是否达到样本门槛

判断：

| 广告位状态 | 判定 | 动作 |
|---|---|---|
| 表现好且花费占比低 | 有效流量拿得不够 | 增加该位置溢价，或小幅提高基础 Bid |
| 表现好且花费占比正常 | 当前结构健康 | 保持 |
| 表现差且花费占比高 | 低效位置消耗预算 | 降低该位置溢价，必要时降到 0 |
| 样本不足 | 不能判断 | 保持观察，不强调 |
| 整体状态未路由到广告位诊断 | 不进入广告位优化 | 保持，不拆广告位 |

### 如何控制不同广告位花费

| 目标 | 控制方式 |
|---|---|
| 想要更多 TOS 花费 | 增加 TOS 位置溢价，或提高基础 Bid |
| 想要更多 ROS 花费 | 增加 ROS 位置溢价，或提高基础 Bid |
| 想要更多 PP 花费 | 降低基础 Bid，并把 TOS / ROS 溢价降到 0 |
| PP 表现好，其他位置也好 | 不需要调整 |
| TOS / ROS 表现差，PP 表现好 | 降低基础 Bid；TOS / ROS 溢价降到 0；保留 PP 获取能力 |
| TOS 表现好，ROS / PP 差 | 提高 TOS 溢价；降低 ROS / PP 溢价 |
| ROS 表现好，TOS / PP 差 | 提高 ROS 溢价；降低 TOS 溢价，基础 Bid 不盲目提高 |

提高基础 Bid 会同时影响多个广告位，不是精准控制单一位置。只有位置溢价才能更直接控制 TOS / ROS。

## 广告商品诊断

广告商品层必须看 ASIN/SKU、父子体、尺寸、花费、订单、ACOS、CVR、CPA、CTR、变体表现。

判断方向：

- 效果差的商品优先暂停或换品。
- 效果好的商品不提出拆分重建建议。
- 同一广告组内商品表现差异大时，才考虑拆分或合并。
- 样本不足时只能观察。

## 搜索词与词根诊断

搜索词再投放、词根聚合、ABA 匹配的细则见：

`agents/search-term-reinvestment.md`

老品推广不得在本文件内另建词根映射。必须直接调用 `agents/search-term-reinvestment.md` 的统一 ABA 多词根归属集合，与用户单独发起的词根聚合使用完全相同的结果：完整搜索词自身命中 ABA 时保留完整词根，同时继续聚合内含 Phrase 词根或高置信 Broad 基础词根；严格隔离 `water bowl`、`water fountain`、`water dispenser` 等不同产品意图，并分别保留每个词根的 ABA 排名。没有可靠 ABA 入口时标记未归类，不得为了生成老品动作而强行归类。多归属词根指标不能横向求和后当作当前链接总计。

核心老品规则：

- 单搜索词：定位匹配、跨周期重复成交、CPA/CVR 稳定；单搜索词根点击 `>=20`、订单 `>=2`，且 CPA <= 链接近 7/14 天平均 CPA 阈值，可拉词组/广泛。
- 词根聚合：调用统一 ABA 多词根归属集合，保留原始搜索词及逐条 `搜索词-词根` 回溯；每条归属必须标注 `词组匹配` 或 `广泛匹配`，品牌搜索词同时标注 `品牌词`。这些标签只表示搜索词与 ABA 词根的语义关系，不代表后台实际匹配类型。
- 单词差、词根好：可以把词根列为复投候选；差词只有在完整模式、成熟归因、达到当前品类停止线且 Target 唯一映射时，才可生成 `Negative Exact` 待审批候选。不得把“词根好”本身当作否定差词的充分条件。
- 高花费无订单：花费达到停止线后，完整报表模式仍需满足 `O=0`、成熟归因、唯一 Target 映射和 `DQ_PASS`，才能生成降 Bid 或否定待审批候选；仅搜索词模式只能标记“降 Bid / 否词候选，待投放对象映射”。
- 不相关词：属性或意图与产品冲突时标记为排除候选；可执行否词仍需唯一 Target 映射、成熟归因、数据质量通过和 Validator 验收。
- 样本不足词：保留观察，不做强动作。

### 出单词跨广告产品拓量

当搜索词、投放词或词根已经达到当前类目优质线，且样本和趋势满足 `agents/search-term-reinvestment.md` 的 A 档标准时，可以把该词从 SP 复制验证到 SPV / SB / SBV。

执行边界：

- 必须保留原表现好的 SP 广告，不因新增广告产品而停掉原 SP。
- SPV / SBV 必须有可用视频素材；SB / SBV 必须有品牌资质、Store 或落地页。
- 如果来源 SP Phrase 效果好，可以新增同词 Phrase 逻辑的 SPV / SB / SBV。
- 如果来源 SP Broad 效果好，先看真实出单搜索词是否集中；集中时复制真实出单搜索词或词根，不机械复制 Broad 投放词。
- 只达到正常线、样本不足、近 3 天转差或缺少日期字段时，不跨广告产品，只做 SP 内部迁移或观察。
- 新增广告产品的预算按 CPA 正常线上限设置；低于该值只能写观察预算。

## 趋势判断：主指标 + 辅助指标

趋势主指标必须来自用户明确的经营目标：目标 ACOS、目标 CPA、订单目标、利润目标或结构目标。没有主目标时，趋势只能描述，不能触发动作。

### 指标方向标准

| 指标 | 变好 | 变差 |
|---|---|---|
| ACOS | 下降 | 上升 |
| CPA | 下降 | 上升 |
| CVR | 上升 | 下降 |
| 订单 / 利润 | 上升 | 下降 |

动作判断必须使用互不重叠的窗口：

```text
D0-3
D4-7
D8-14
D15-30
```

滚动 3/7/14/30 天可以继续输出“当前水平”描述，但不得直接比较重叠窗口后形成执行动作。

### 趋势状态与权限

| 状态 | 判定 | 动作权限 |
|---|---|---|
| `RECOVERY` | 主指标改善，且至少一个辅助指标同向改善，没有相反信号 | 可以生成恢复或小幅拓量候选 |
| `DETERIORATION` | 主指标恶化，且至少一个辅助指标同向恶化，没有相反信号 | 达到样本与风险门后可生成收缩候选 |
| `STABLE` | 主指标稳定，辅助指标无有效方向 | 保持 |
| `MIXED_SIGNAL` | 主指标与任一有效辅助指标方向相反，或辅助指标之间同时改善和恶化 | 只观察，不生成强动作 |
| `INCONCLUSIVE` | 主指标没有同向辅助证据、样本不足或窗口缺失 | 只观察并补数据 |

原“持续好 / 近期转差 / 连续恶化 / 恢复 / 震荡”可作为读者说明文字，但不能绕过上表的主指标与辅助指标门槛。任何趋势动作还必须通过数据质量、整体状态、对象映射和 Validator。

## 结构诊断

- 自动、广泛、词组混在同一结构且无法归因时，效果差的类型优先关闭，最后才考虑拆分重建。
- 效果好的类型不提出拆分重建建议。
- 同一关键词在多个相同目的广告组重复投放时，标记内部竞争并提出合并或隔离。
- 预算过度分散、类型混装、无法归因时，才考虑重建。

## 数据聚合层级

必须至少能说明使用了哪些层级：

- 产品层：ASIN / SKU，用于判断产品目标、总广告效率和预算空间。
- Campaign 层：用于判断预算、目标和竞价策略。
- 广告组层：用于判断结构、类型和内部竞争。
- 投放对象层：Keyword / Target ASIN，用于判断 Bid、迁移、保留或暂停。
- 买家搜索词层：用于发现真实流量、词根和否定词。
- 广告位层：TOS / ROS / PP，用于判断溢价和流量位置。

如果缺少当前链接自己的搜索词，不得用类目历史出单词库补位生成老品优化方案；只能输出“基于类目历史的选词参考”。如果有当前链接的历史搜索词但缺 Campaign、广告组、广告位、预算、Bid 或趋势报表，必须启用上文的“有限数据老广告优化模式”：可以输出词根层的评分和候选优化方案，但必须逐项标记无法准确判断的后台模块。
- 时间层：小时 + 3/7/14/30 天，用于判断消耗速度、趋势和异常。

## 动作仲裁与独立 Validator

所有局部模块先生成“候选动作”，再按对象仲裁：

1. 同一 `Campaign_ID / Ad_Group_ID / Target_ID / Keyword_ID` 每批只能保留一个主动作。
2. 暂停被选为主动作时，针对同一对象的加预算、降预算、提 Bid、降 Bid、启用或广告位主动作全部撤销。
3. 同一对象同一优先级出现加/降预算、提/降 Bid、暂停/启用等相反动作时，不得取平均或任意选择；该对象整组动作标记 `BLOCKED`。
4. 搜索词多词根归属只增加证据，不增加重复动作。动作去重键至少包含 `ASIN + Search_Term + Ad_Product + Match_Type + Traffic_Role`，后台实施仍以不可变 ID 为准。

仲裁后的候选动作必须交给独立 Validator，结果只有：

- `AUTO_PASS`：数据、映射、字段、状态和冲突校验通过；V1.4 仍需人工执行确认。
- `APPROVAL_REQUIRED`：高影响、低样本停止例外、数据警告或其他需要人工复核的候选。
- `BLOCKED`：不得进入执行表。

完整执行行必须包含：`Action_ID`、`Campaign_ID`、`Ad_Group_ID`、`Target_ID / Keyword_ID`、`action_level`、`current_value`、`proposed_value`、`unit`、`precondition`、`rollback_value`、`input_snapshot_id`、`expected_current_value`、`generated_at`、`expires_at`、`Rule_ID`、`Threshold_ID`。只有“提高 10%”“降低一些”等方向而没有当前值、目标值和回滚值的行，只能作为建议，不得进入执行表。

## 最终执行顺序

1. 冻结输入快照并输出 `input_snapshot_id`；先完成数据质量和唯一整体状态。
2. 先决定保留什么，再生成预算、Bid、广告位、投放对象、新增或重建的候选动作。
3. 对同一对象做动作去重和冲突仲裁；相反动作不能同时保留。
4. 由独立 Validator 输出 `AUTO_PASS / APPROVAL_REQUIRED / BLOCKED`。
5. 只有非 `BLOCKED` 且字段完整的动作才能进入人工执行清单；执行前再次核对 `expected_current_value` 与后台当前值。
6. V1.4 不自动操作 Amazon 后台。人工实施后必须记录成功、跳过、部分成功或失败，并保留回滚值供复盘。

## 输出说明要求

老品广告架构或优化方案必须在第一张核心表下方追加一段 `判断依据与设计逻辑`。该说明只用自然段，不新增表格、不新增 sheet，内容必须说明：

- 使用了哪些当前链接 / 当前 Campaign / 当前广告组报表，以及观察周期。
- 整体效果、搜索词、投放对象、广告位、广告商品、预算节奏、趋势和结构中，哪些层级真正影响了本次设计。
- 为什么保留、优化、新建、合并、拆分、重建、跨广告产品拓量或暂停。
- 广告组命名、标准最低日预算、Bid、广告位溢价和匹配方式的主要依据。
- 为什么没有选择其他动作，例如整体达标所以不拆广告位、样本不足所以只观察、缺少映射所以不给后台执行动作。

说明段必须把关键判断按来源标注清楚：

- `【当前报表】`：说明来自当前链接 / Campaign / Ad Group 的搜索词、投放对象、广告位、广告商品、预算、趋势和设置表的结论。
- `【当前历史搜索词】`：说明只使用当前链接搜索词汇总 / 每日明细的观察周期、词根订单、CVR、ACOS 和历史词根优化分；不得写成已知道具体投放对象或广告组。
- `【品类阈值/用户固定规则】`：说明哪些结论来自 `category data thresholds.md`、CPA 正常线上限作为标准最低日预算、目标 ACOS / CPA / CVR、花费<2单、点击<2单、广告位先看整体效果、统一广告组命名等固定规则。
- `【流量结构打法】`：如果调用了类目流量结构或竞对词表，说明它只影响新广告入口布局、预算集中/分散或补入口判断，不得覆盖当前报表表现。
- `【历史数据】`：如果调用了同类历史搜索词，只能作为新增词候选或可复用词参考；不能作为老品暂停、否词、降 Bid、广告位调整或预算动作的数据源。
- `【人工输入/业务目标】`：说明用户给定的订单目标、利润、库存、Coupon、Review、预算上限如何影响放量或收缩。
- `【缺失数据】`：说明缺少哪些报表导致只能给方向、不能给后台可执行动作。

说明段只解释表格中已经给出的动作，不能新增表格外执行项。
