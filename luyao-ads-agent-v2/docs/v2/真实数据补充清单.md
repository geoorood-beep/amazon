# V2 第一阶段真实数据补充清单

## 结论

当前基础架构、数据合同、动作合同、冲突仲裁、独立Validator、人工执行确认和复盘资格判断可以直接开发，不需要类目阈值或真实报表。

以下内容必须有真实数据后才能完成：

- Amazon原始报表字段映射；
- 跨报表对账口径和容差；
- 当前值与后台对象ID的可靠映射；
- 历史批次回放；
- 动作幅度、批次预算上限和风险校准；
- 试运行效果复盘。

类目阈值和唯一规则源目前均保持`UNDECIDED`。生产Validator会主动阻断，不会用默认值补齐。

## 第一组：建立真实报表解析器时必须提供

建议先选择一个真实老品链接和一个完整的30天观察周期，提供Amazon原始导出文件，不要手工删列或合并。

| 优先级 | 标准报表名称 | 主要用途 |
|---|---|---|
| 必须 | `SP搜索词-按词-每日明细` | 搜索词逐日趋势、近3天变化、归因成熟检查 |
| 必须 | `SP搜索词-按词-汇总` | 周期累计表现及与每日明细对账 |
| 必须 | `SP投放对象 / 关键词 / 商品投放报告` | Target、Keyword、ASIN、匹配方式、Bid和搜索词映射 |
| 必须 | `SP广告位报告` | TOS、ROS、PP周期表现 |
| 必须 | `SP广告商品报告` | ASIN、SKU、父子体和广告商品表现 |
| 必须 | `Campaign / Ad Group 设置表` | Campaign ID、Ad Group ID、预算、Bid、状态和名称 |

同一数据包还必须说明：

| 字段 | 要求 |
|---|---|
| Marketplace | 例如`US` |
| Account / Profile | 使用稳定内部标识，不使用店铺昵称代替 |
| Timezone | 报表采用的账户时区 |
| Currency | 例如`USD` |
| Attribution Window | Amazon报表实际归因窗口 |
| Period Start / End | 六张报表必须可以对齐 |
| ASIN / SKU | 当前链接和广告商品映射 |
| 文件来源 | Amazon后台、第三方ERP或人工维护 |

## 第二组：确定跨报表对账标准时需要提供

仅有一批文件只能开发字段映射，不能确定长期容差。建议至少提供三个历史周期：

1. 一个报表完全正常的周期。
2. 一个存在延迟归因、退款或日汇总差异的周期。
3. 一个发生Campaign、Ad Group或Target设置变化的周期。

每个周期需要一份人工确认结果：

- 哪张报表是Campaign预算与状态的唯一事实源；
- 哪张报表是Target Bid与状态的唯一事实源；
- 搜索词订单和销售额以哪份报表为准；
- 汇总与每日明细允许出现哪些已知差异；
- 超过什么差异必须停止生成方案。

没有这些资料时，系统只能输出`RECONCILIATION_NOT_CONFIGURED`，不得`AUTO_PASS`。

## 第三组：历史回放时需要提供

每个历史批次需要保存：

| 数据 | 最低要求 |
|---|---|
| 执行前六张报表 | 能还原当时看到的数据 |
| 当时的业务目标 | 订单目标、目标ACOS或CPA、预算上限 |
| 当时的设置快照 | Campaign预算、Target Bid、Placement和状态 |
| 实际执行记录 | 改了什么、从什么值改到什么值、执行时间 |
| 执行后报表 | 覆盖完整观察周期和归因窗口 |
| 外部事件 | 价格、Coupon、库存、Listing、促销等变化 |
| 人工期望结论 | 该批次正确动作或应BLOCK的原因 |

`reference/category-history/`中的历史搜索词只能用于选词参考，不能代替上述老品批次报表。

## 第四组：试运行后才能产生

- 人工执行确认；
- 实际值与计划值偏差；
- 执行后完整归因数据；
- 二次调整记录；
- 外部事件隔离结果；
- Rule ID和Threshold ID的支持、反对或不可判定证据。

这些数据用于复盘Agent，不应在没有真实执行时模拟成线上证据。
